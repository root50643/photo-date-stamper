# 手動驗證清單

本文件是發行前的人工檢查程序，**未勾選的項目表示尚未記錄人工實測結果**。已通過的自動化測試另記於 [verification.md](verification.md)，包含 Chrome／Edge 的 EXIF 方向 1–8 像素驗證；此處保留相應人工比對項目，不表示該功能完全未驗證。

自動化目錄流程使用瀏覽器原生 OPFS handles 讀寫網站私有檔案系統，並替代 `showDirectoryPicker` 的傳回值；取消與拒絕權限由 stub 模擬。這些測試不能代替 Windows 原生目錄選擇器、使用者磁碟目錄、作業系統授權或目視影像品質驗證。

## 測試資料準備

準備一個來源目錄、一個手動指定的輸出目錄及一個空目錄。來源目錄至少包含：

- 橫式、直式、正方形 JPEG；小尺寸圖片及高解析照片。
- 帶透明區域的 PNG、WebP，以及普通不透明 PNG、WebP。
- 同一張有上下／左右方向標記的 JPEG，分別設 EXIF Orientation 1–8；保留八張的預期朝向參考圖。
- 副檔名大寫、中文檔名、空白檔名、同名不同副檔名。
- 一張損壞 JPEG、一個內容與副檔名不符的檔案、動畫 PNG／WebP、GIF／HEIC 等不支援格式。
- 子目錄內另放照片；來源中的 `dated` 子目錄也放一張照片。
- 輸出目錄先放 `photo.jpg`、`photo_1.jpg`；另一個案例放同名目錄，測試命名避讓。

## 基本流程、目錄及授權

- [ ] HTTPS／localhost 可操作；未支援環境顯示清楚說明。
- [ ] 點選工作目錄開啟原生選擇器，取消後可重試。
- [ ] 拒絕讀取授權後顯示原因，重新選擇並授權後可載入。
- [ ] 僅列出來源本層支援副檔名；子目錄及 `dated` 內的照片未列入。
- [ ] 空目錄或只有不支援格式的目錄顯示無照片，不能開始空批次。
- [ ] 選來源後顯示預設 `dated` 輸出位置；尚未開始前不建立該子目錄。
- [ ] 自訂輸出目錄與恢復預設輸出均有效。
- [ ] 開始前出現需要的寫入授權；拒絕後沒有產生照片，仍可重新開始。
- [ ] 若來源唯讀，選另一個可寫入輸出目錄後可處理。
- [ ] 若來源已有一般檔案 `dated`，錯誤可理解，改選輸出目錄後可完成。
- [ ] 重新整理網頁後須重新選目錄，照片不會被自動讀取或繼續處理。

## 日期、外觀及設定

- [ ] 首次載入的日期是裝置當天，預設格式是 `YYYY/MM/DD`。
- [ ] 日曆與文字輸入可指定同一天；無效日期不能開始處理，閏年日期正確。
- [ ] 四種格式均正確；`/`、`.`、`-` 清楚可見，沒有缺字方框或錯誤符號。
- [ ] 黃色預設為 `#FFD700`，文字帶細暗色描邊。
- [ ] 初始字級為校正後短邊的 3%，右／底間距分別為寬／高的 3%。
- [ ] 滑桿與數字輸入同步，切換不同尺寸照片後保持比例。
- [ ] 拖曳日期會更新位置數值；日期及描邊不可拖出照片。
- [ ] 極小圖片、極大字級及四邊位置的文字均不被裁切，必要時縮小。
- [ ] 分別恢復位置、大小、顏色僅重設該項；全部恢復也重設日期格式。
- [ ] 重新整理後外觀及日期格式仍保留，但日期值回到裝置當天。
- [ ] 匯出 JSON 再修改畫面，匯入後恢復設定；檔案沒有照片或目錄資訊。
- [ ] 損壞 JSON、未知版本、不支援日期格式、無效顏色及超界數值會被拒絕，原設定不變。
- [ ] 禁用本機儲存或使其失敗時，介面可繼續操作並說明無法保存。

## 影像與輸出

- [ ] 橫式、直式、正方形及小尺寸的預覽／輸出位置、顏色、格式一致。
- [ ] EXIF 方向 1、2、3、4、5、6、7、8 各自符合參考圖，沒有二次旋轉或錯誤鏡射。
- [ ] 方向校正後像素尺寸正確；無需旋轉的照片沒有被縮圖輸出。
- [ ] PNG／WebP 的透明區域仍透明；實際輸出格式與副檔名相符。
- [ ] JPEG／WebP 輸出可正常開啟，目視確認可接受的重編碼品質。
- [ ] 動畫、損壞或不支援內容清楚標示；單張失敗不阻止正常照片繼續。
- [ ] 同名輸出使用 `_1`、`_2` 等可用名稱，不覆寫已有照片或同名目錄。
- [ ] 來源與輸出選同一目錄時產生新名稱，本批新增檔案不會再被加入。
- [ ] 再次執行同批次會新增編號檔案；沒有覆寫第一次輸出。
- [ ] 比對來源 SHA-256，所有原始檔案內容相同。
- [ ] 對照 README 理解 EXIF、GPS、ICC 不保證保留；不把檔案大小或 metadata 相同當作驗收條件。

## 批次進度、取消與錯誤

- [ ] 處理期間來源、輸出、日期與外觀控制項停用；清單與進度仍更新。
- [ ] 成功、失敗與未處理數量吻合，進度分母固定為載入的照片數。
- [ ] 中途取消會先完成當前照片，不再開始下一張；已完成輸出可開啟。
- [ ] 取消／完成後控制項恢復，重跑可用；取消不假裝全部完成。
- [ ] 單張解碼失敗後仍處理下一張，清單保留可理解的原因。
- [ ] 寫入權限撤銷、輸出裝置中斷或磁碟空間不足時停止整批並說明；已輸出檔案仍可用。
- [ ] 修復輸出環境後可重新選目錄重跑，來源維持不變。

## 大量照片與部署

- [ ] 準備至少 200 張混合尺寸照片，記錄耗時、最大尺寸、總大小與瀏覽器記憶體走勢。
- [ ] 處理時可操作取消，頁面不持續凍結；記憶體不因保留每張完整解碼圖片而線性累積。
- [ ] 大量批次取消及再次執行後，記憶體能回收；少量暫存或瀏覽器延遲回收不直接判失敗。
- [ ] 單張超過可用記憶體／Canvas 上限時顯示失敗，不以空白輸出冒充成功。
- [ ] 本次發行依序執行 `pnpm check`、`pnpm test`、`pnpm build`、`pnpm test:browser`，將摘要附在紀錄；瀏覽器測試前必須重建 `dist/`。
- [ ] 在實際 Pages 專案子路徑載入時 JS、CSS、字型及 Worker 無 404。
- [ ] 正式 HTTPS 網址完成一批真實目錄讀寫，包括預設輸出與手動輸出。
- [ ] 網路面板沒有照片上傳請求；網站所需字型從網站自身載入。

若自動化測試通過但原生選擇器、權限或手動案例未測，發行紀錄應分別標示，不能以 Chromium 自動化通過推論所有 Chrome／Edge 真實目錄流程均已驗證。
